报告与网页演示：审计记录的三个视图

目标：讲清"JSON 主格式 + 多视图"的架构、共用渲染器、XSS 两道关、实验台的安全设计。

5.1 架构：一份数据，三种视图

引擎产出的审计记录（audit dict）是主格式，三种视图都只是它的渲染：

视图用途实现
JSON存档、机器处理、diffrender_json（就是 json.dumps）
纯文本课堂演示、终端直读render_text（格式与计划书第 5 节一致）
独立 HTML正式报告、离线可存档可打印build_html：样式+渲染器+数据全部内嵌单文件
关键设计

网页实验台和 HTML 报告共用同一个 JS 渲染器（static/report.js）—— 两边视觉永远一致，只维护一份代码。这就是为什么 HTML 报告需要启用 JavaScript 才能显示 （原始数据仍在页面源码的 cbl-data 里）。

5.2 网页实验台（webui.py）

纯标准库 HTTP 服务（零依赖），五个接口：

接口干什么
GET /页面（demo.html）
GET /static/*共用渲染器与样式
GET /api/init初始源码、提问、材料目录
POST /api/analyze编译 + 组装 → 页面要的全部数据（诊断、逐块视图、审计、Prompt）
POST /api/report同上参数 → 独立 HTML 审计报告（下载）

核心函数是 analyze()：一次调用跑完整条流水线，返回全部可 JSON 序列化的结果， 包括每段/每轮材料的状态（保留 / 部分保留 / 并入摘要 / 丢弃）——这就是"AI 实际看到了什么"的数据来源。

5.3 安全设计（局域网演示的底气）

  • 路径沙箱：网页允许编辑源码，source 字符串被限制在材料目录内——写 "../../任意文件" 会被拒绝读取（有专门测试 case_webui_source_sandbox）。
  • 请求体上限 256KB：只看请求头就拒绝，不读包体。
  • 缺省只监听 127.0.0.1；--lan 才开放局域网（手机演示用）。
  • XSS 两道关：渲染器只用 DOM API + textContent，从不拼 HTML 字符串；内嵌 JSON 把 < > & 转成 \u 形式，材料里即使有 </script> 也截断不了脚本。

5.4 单位状态判定（曾经的 bug）

"每段材料到底保留了没有"怎么判定？看原文是否出现在最终文本里：完整出现 → 保留；只出现首尾片段 → 部分保留； 位于保留原文之前且有摘要 → 并入摘要；否则 → 丢弃。

曾经的 bug

摘要会引用早期轮次的首句，导致这些轮次被误判为"部分保留"，页面显示"保留 7/8 轮"而实际只保留了 4 轮。 修法："并入摘要"的判断必须先于"部分保留"，并加了回归测试。——启发式判定的顺序就是语义。

5.6 本课自测

1. 为什么 HTML 报告用 JS 渲染而不是 Python 直接拼好 HTML？

代价是报告需要启用 JS——原始数据仍在页面源码里兜底。

2. 防 XSS 的两道关是什么？

材料内容是不可信输入，两道关分别守住"渲染"和"数据嵌入"两个注入点。

3. 演示服务为什么缺省只监听 127.0.0.1？

--lan 是给手机演示用的显式开关——功能与安全的取舍要做成显式选择，不是默认开放。
