语义检查与 IR：意思通不通，和编译期的"交接单"

目标：讲清九条约束各自防什么、表驱动怎么落地、属性文法体现在哪、为什么要有 JSON 中间表示。

3.1 语法对了，意思就对了吗？

生活类比

"我吃饭了桌子"语法结构没错（主谓宾齐全），但意思不通。同理：cap: 7000 + cap: 7000 两个块各自合法，但加起来超过 window 8000 × 0.9 = 7200——这种错误必须等所有块读完， 在整棵 AST 上才能发现。这就是语义检查存在的理由。

3.2 九条约束一览

约束防什么错误目录编号
① 预算总量各块 cap 之和 ≤ window × marginE101、E102
② 无解判定must_keep 总额超窗 → 逻辑上无解，编译期就报E201
③ 枚举合法性priority / overflow / on_violation 取值合法（复核）E301~E303
④ 命名唯一block 与 rule 共用一张符号表，重名报错E401
⑤ 参数适配keep_recent 为正整数，且只配 summarize / sliding_windowW501、E502
⑥ 来源合法内置来源只有三个；字符串一律放行当文件路径E601
⑦ 断言合法度量必须预定义；静态断言编译期直接求值E701、R702
⑧ 必填项完整source、cap 必须显式声明且为正E801~E803
⑨ 保护一致must_keep 的 overflow 只能是 error——死保不可裁剪E901

3.4 实现方式：错误目录 + 表驱动

semantic.py 的设计就两句话：

  • 错误目录 CATALOG（16 项）：枚举全部可静态发现的错误，每项一个编号和说明模板；
  • 检查表 CHECKS：每个检查函数负责一条约束，产出目录中的诊断；主流程只有三行——全跑一遍、收集、按行号排序。

新增一条约束只需三步：目录加一行 → 写函数挂进 CHECKS → 测试里加一对正反例。 漏写测试会被 case_catalog_covered 自动拦下（第 6 课细讲）。

3.5 属性文法体现在哪（答辩高频题）

核心概念
  • 综合属性（自底向上）：total_reserved = 各块 cap 之和，从叶子（block）自底向上汇总到 Program。
  • 继承属性（自顶向下）：window、margin 从根节点向下传给各项检查使用。
  • 约束 = 定义在这些属性上的谓词（①②⑦都建立在它们之上）。相对 cap 在语法阶段已折算成绝对值，语义层无感。

3.6 编译期断言 vs 运行期断言

两条度量、两种求值时机：

度量含义求值时机为什么
total_reservedΣcap编译期（semantic）只依赖声明的 cap 和 window
every_block_min_tokens压缩后各块有效额度的最小值运行期（engine）取决于本次可用额度 B，编译期不知道

两类断言失败都按规则自己的 on_violation 定级：error → 编译失败 / 拒绝组装；warn → 记警告不阻断。

3.7 IR：JSON 组装计划

通过语义检查的 AST，经 ir.py 一次遍历翻译成 JSON 计划（语法制导翻译：每类 AST 节点对应一个 JSON 对象）。 所有缺省值在这一步全部显式写出，还附上了引擎求值需要的拆解字段（metric/op/operand），引擎不必再解析断言原文。

思考题：为什么要 JSON 中间表示，不直接让引擎读 AST？

① 编译器与引擎解耦，可以各自替换演化（引擎入口还有 validate_plan 校验这份契约，见第 4 课）； ② JSON 可存档、可 diff、任何语言都能读；③ 教学上它就是"目标代码"，让编译器有明确的输出物。

按"三步法"新增 W1001：cap 小于 64 给警告：① CATALOG 加一行； ② 写一个检查函数挂进 CHECKS；③ 在 tests/run_tests.py 的 PAIRS 里加一对正反例。 提示：故意先做①②不做③，看 case_catalog_covered 怎么提醒你。

走完这一圈，表驱动就长在手里了——这是本课最重要的一次动手。

3.9 本课自测

1. 约束②（无解判定）和约束①（总量约束）都涉及求和，区别是什么？

②的语义是"这个预算永远不可能执行"，所以编译期直接报错而不是运行期失败。两条都在编译期。

2. 约束③（枚举合法性）语法层已经拦住了，语义层为什么还要查一遍？

同一个防御思路也出现在引擎入口的 validate_plan——不信任上游，契约每道关都验。

3. R702 的级别为什么有时是"错误"有时是"警告"？

CATALOG 里 R702 的级别字段是 None，造诊断时按规则的 on_violation 填入。

4. IR 里为什么既有 assert 原文字符串，又拆了 metric/op/operand 三个字段？

一次解析、两处使用：人读原文，机器读结构。
