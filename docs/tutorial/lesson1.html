词法分析：把字符切成 Token

目标：能手推任意一小段 CBL 源码的 Token 序列，讲清最长匹配、关键字识别、行列号维护。

1.1 词法分析在干什么

源文件对计算机来说只是一串字符：window 8000 ;。词法分析器（lexer，也叫 Scanner）的工作， 是像人读句子先分词一样，把字符流切成一个个有类型的"单词"——Token。

生活类比

读英文句子 "I love you" 时，你不会一个字母一个字母理解，而是先分成三个词。 词法分析就是编译器的"分词"阶段；行号列号则像查字典时的页码——出错时能指回原文位置。

1.2 Token 的四个字段

打开 cbl/tokens.py，Token 只有四个字段（dataclass，自带打印与比较）：

字段例子作用
kind 类型KEYWORD / IDENT / INT / FLOAT / STRING / SYMBOL / EOF语法分析只认它（第 2 课）
value 字面值"window"、"8000"原文是什么
line / col行 1 列 8报错定位的依据（我们 11 月刚把列号也加进了语法报错）

1.3 核心结构：一个循环 + 七个分支

tokenize()（lexer.py）的全部智慧就是一个 while 循环：看当前字符是什么，跳进对应分支。 每个分支做两件事：消耗属于自己的字符，产出一个 Token。七个分支：

#分支识别什么关键动作
①空白空格 / Tab / 换行跳过，不产出
②注释# 到行尾整行丢弃
③字符串"..."不跨行、不转义；少右引号 → 词法错误
④数字8000、0.9最长匹配（见 1.4）
⑤标识符/关键字chat_history、window读完整词再查关键字表
⑥双字符符号<=、>=必须排在单字符之前
⑦单字符界符{ } : ; * %直接产出

一个字符七不认 → 词法错误（带行列号）。

1.5 四个必须掌握的细节

细节 1：最长匹配

读到 8000 时，看见 8 不能就产出——要连续读完所有数字。读到 0.9 时， 只有"小数点后还是数字"才算 FLOAT（所以 8000; 里的 ; 不会被吞）。 同理 <= 必须先于 < 判断。原则：永远匹配能匹配的最长 Token。

细节 2：标识符只认 ASCII

lexer.py 里写的是 ch.isascii() and ch.isalpha()。 为什么不能只写 isalpha()？因为 Python 把汉字也算字母，block 历史 {} 就会被当成合法块名—— 而文法规定标识符是 [A-Za-z_][A-Za-z0-9_]*。词法分析器必须严格实现正规式，不能偷懒用内置判定。

细节 3：关键字是"先当标识符读，再查表"

window 不是被直接认成关键字的：先按标识符规则读完整个单词，再查 21 个关键字的表 （tokens.py），在表里 → KEYWORD，不在 → IDENT。副作用：关键字自动成为保留字—— block error {} 里的 error 查表命中 KEYWORD，不再是 IDENT，当不了块名。

细节 4：行列号是手工维护的

advance() 每吃掉一个字符就更新位置，遇到换行 line+1, col=1。 没有黑魔法，但全编译器的报错定位都建立在这几行上——包括你在实验台上点击诊断跳行的功能。

1.7 本课自测

1. Token 的四个字段是什么？

kind / value / line / col。后两个是报错定位的依据——没有它们，错误只能报"某处错了"。

2. 为什么双字符运算符（<=）的分支必须排在单字符界符之前判断？

先看两个字符能不能组成双字符符号，不能才退到单字符。这就是最长匹配在符号上的体现。

3. window 是怎么变成 KEYWORD 的？

这个机制让关键字自动成为保留字：它们永远查表命中，永远不会是 IDENT。

4. 字符串为什么"不允许跨行、不处理转义"？

DSL 的设计哲学：够用就好。真要支持转义，改动点在字符串分支——遇到 \ 时多看一个字符。
思考题：如果允许字符串转义（如 \" 表示引号），lexer 的字符串分支要改哪里？

现在字符串分支是"读到引号就停"。支持转义后，读到 \ 时要多吞一个字符（跳过它的特殊含义）， 并决定 value 里存原文还是转义后的真实字符。注意：行号列号记的是原文位置，不受转义影响。
